# twitch-bot

Twitch-бот стримера `nglzzz`, дополненный мини-сайтом на уже существующей Node.js + Docker инфраструктуре.

## Что теперь есть

- главная страница `/` с блоком о стримере;
- встроенный Twitch-плеер и встроенный Twitch-чат;
- отдельная страница `/stats` со статистикой по viewer-срезам и chat-логам;
- JSON-эндпоинты `/api/streamer/summary` и `/api/streamer/stats` для будущих интеграций;
- логирование новых сообщений чата в `MongoDB`, если база подключена.

## Викторина в чате

- `!викторина` или `!в` запускает 10 раундов с загадками. Ответ отправляется обычным сообщением в чат.
- На слово даётся 60 секунд; через 30 секунд бот сообщает первую букву и длину слова. Между раундами — 5 секунд.
- Первый верный ответ приносит 1 очко. Регистр и различие `е`/`ё` не учитываются.
- `!в очки` показывает свои очки, `!в топ` — пятёрку лидеров. Очки общие для всех стримов и сохраняются в SQLite по Twitch ID.
- На странице `/stats` во вкладке «Викторина» отображается топ-20 игроков за всё время. Эти данные также доступны в поле `quizLeaderboard` ответа `/api/streamer/stats`.
- Зрители могут запустить игру только во время эфира. Стример может запустить её и офлайн, а также остановить командой `!в стоп`.
- Если на текущем эфире игру ещё не запускали, она автоматически начинается через два часа от времени начала эфира Twitch. Статус проверяется каждые 30 секунд.
- Ручной запуск отменяет автозапуск на этом эфире. Завершение эфира останавливает игру; новый эфир получает собственный отсчёт. Отметка запуска сохраняется после перезапуска бота, активные раунды — нет.

Вопросы пополняются через существующую интеграцию с нейросетью: при нехватке запаса бот запрашивает до 20 вопросов на русском одним JSON-ответом и сохраняет их в SQLite. В чат отправляется только вопрос; ответ и допустимые варианты используются для проверки сообщений. Во время раунда запросов к модели нет. Первый запуск может занять до 15 секунд на генерацию.

Генератор использует `QUIZ_AI_MODEL`, а если она не задана — `CHAT_GPT_MODEL` с уже настроенным ключом провайдера. Он работает отдельно от истории обычного чата и делает один запрос к выбранной модели без цепочки запасных провайдеров. Для бесплатного маршрута OpenRouter укажите `QUIZ_AI_MODEL=openrouter`, `OPENROUTER_MODEL=openrouter/free` и `OPENROUTER_API_KEY`. Лимиты и доступность бесплатных моделей задаёт OpenRouter; другие выбранные модели могут быть платными.

JSON проверяется по формату, длине, наличию ответа в тексте вопроса и дубликатам. Фактическую правильность ответа такая проверка не гарантирует. Выбранные вопросы не выдаются повторно на том же стриме, в том числе после перезапуска бота; в новых эфирах сохранённая база может использоваться снова. При сбое модели выдаются ещё не использованные вопросы из базы. Начальная подборка `src/data/quizWords.js` служит резервом. Если запас исчерпан, игра не повторяет старые вопросы, а предлагает попробовать позже.

Таблицы `quiz_score`, `quiz_stream`, `quiz_question` и `quiz_question_use` создаются при обычном запуске приложения существующим механизмом инициализации SQLite; отдельный скрипт миграции не нужен.

## Озвучка и OBS

Страница `/speak` показывает чат и управляет озвучкой. На ней есть кнопка для копирования
готового URL чистого чата в OBS. Добавляйте его как источник **«Браузер»**:

- `/speak?overlay=1` — прозрачный оверлей с озвучкой и сообщениями;
- `/speak?overlay=chat` — прозрачный оверлей только с чатом, без панели и аудио.

Оверлей автоматически отображает сторонние эмоуты 7TV, BetterTTV и FrankerFaceZ для
Twitch-канала. Каталоги обновляются в памяти раз в 30 минут; при недоступности одного
провайдера остальные продолжают работать.

### Внешние платформы чата

Оверлей принимает нормализованные сообщения от адаптеров Kick, VK Play, W.TV, GoodGame,
Trovo, WASD, YouTube и других площадок. Задайте длинный случайный
`OVERLAY_INGEST_TOKEN` в `.env` и отправляйте из адаптера запрос:

```http
POST /api/chat/messages
Authorization: Bearer <OVERLAY_INGEST_TOKEN>
Content-Type: application/json

{
  "platform": "kick",
  "nickname": "viewer",
  "message": "Привет из Kick!",
  "timestamp": 1783920000000
}
```

Поле `platform` используется как метка в чате; известные значения: `kick`, `vkplay`,
`w.tv`, `goodgame`, `trovo`, `wasd`, `youtube`, `twitch`. Неизвестные названия также
передаются как метка, поэтому для новой платформы не требуется менять оверлей.

## Источники данных мини-сайта

- **Twitch API** — live-статус, название стрима, категория, viewer count;
- **Mongo / `viewer`** — история viewer-срезов, средний и пиковый онлайн;
- **Mongo / `chatLog`** — последние сообщения и топ чаттеров;
- **оперативная память бота** — fallback, если MongoDB временно недоступна.

## Локальный запуск

```bash
npm install
npm start
```

Проверка, что view-model сайта собирается без ошибок:

```bash
npm test
```

## Запуск в Docker

Сборка образа:

```bash
docker build -t nglzzz/twitch-bot:1 -f docker/app/Dockerfile .
```

Запуск контейнера:

```bash
docker run -p 85:8080 nglzzz/twitch-bot:1
```

## Запуск через docker-compose

```bash
docker-compose up --build
```

После старта проверь:

- `http://localhost/` — мини-сайт;
- `http://localhost/stats` — подробная статистика;
- `http://localhost/api/streamer/summary` — краткая JSON-сводка;
- `http://localhost/api/streamer/stats` — подробная JSON-статистика.

## Примечания по окружению

- для Twitch API нужен `TWITCH_API_CLIENT_ID`; токен можно задать в `/admin/settings`, через
  `TWITCH_ACCESS_TOKEN` или legacy-файл `storage/twitch-token` (приоритет именно в этом порядке);
- Boosty token также задаётся в `/admin/settings`, а без него читается из `storage/boosty-token`;
- для статистики из БД нужна рабочая Mongo-конфигурация (`MONGO_*`);
- Twitch embed требует корректный `parent` hostname, он вычисляется автоматически из запроса;
- если проект стоит за reverse proxy / docker ingress и наружный домен отличается от того, что видит контейнер, задай `SITE_PUBLIC_HOST=your-domain.example` в `.env`.
